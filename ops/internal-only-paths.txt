# 用途は2つ:
#   1. ops/check-branch-base.sh  — internal-dev 宛の PR が「共有物しか触っていない」ときに落とす。
#      共有物は public-dev 起点で作らないと main へ届かない（実例: 2026-07 の docs 整理）。
#   2. ops/sync-public-to-internal.sh — 衝突時にどちらを採るかの目安（ここに載る物は internal 版が正）。
#
# 書式: 1行1パターン。`#` 始まりはコメント、空行は無視。末尾 `/` はディレクトリ配下すべて。
# パターンは git diff --name-only の出力（リポジトリルート相対）に対して前方一致で照合する。
#
# 追加するとき: 「Public 版に出しても差し支えないか」を先に考える。差し支えないなら
# ここに足すのではなく public-dev 起点で作り直すこと。ここは "Public に出せない物" の一覧であり、
# "とりあえず internal で作った物" の一覧ではない。
