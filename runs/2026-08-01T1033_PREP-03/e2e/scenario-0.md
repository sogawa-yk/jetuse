# シナリオ0 — 抽出口 `POST /api/extract`（取り込まない）

架空のスキャン PDF `jetuse-spike-prep03-設備点検報告書スキャン.pdf`（**テキスト層なし**・日本語・2 ページ）を実 API に渡した。
**保存はしない**ことを、前後のファイル一覧の件数で確認している。

- HTTP ステータス: **200** / チャンク数: **2**
- 取り込み前後のファイル数: 0 → 0（増えていないこと）

```
p.1 | L1:L10 | 架空商事株式会社...
p.2 | L1:L9 | 是正処置および交換部品...
```

- 出典の見出しがページ番号（`p.1` / `p.2`）: **True** → `['p.1', 'p.2']`
- OCR した本文に `BRG-7781` が含まれる（空白を無視して比較）: **True**
  / **そのままの一致**: False
- 実際に走った OCR 呼び出し（1 回で 2 ページ分。DU は 5 ページ単位で分割する）:

```
[
  {
    "engine": "ocr",
    "bytes": 134189,
    "pages": 2,
    "seconds": 3.9,
    "mean_confidence": 0.991
  }
]
```

> **DU の日本語 OCR は英数字の連なりに空白を挟むことがある**（`BRG-7781` →
> `BRG - 778 1`）。文字自体は正しく読めており、日本語の語での検索には影響しない。
> 型番の完全一致検索が要る用途では正規化が要る（`docs/verification/PREP-03.md` の残課題）。

## 上限超過（切り詰めずに拒否する）

一時的に OCR 対象ページの上限を 1 に落として同じファイルを投げた:

- HTTP ステータス: **422**（期待 422）
- detail: `OCR が要るページ数が上限を超えました(> 1 ページ)。ファイルを分割してください (limit=ocr_pages)`（どの上限かが書かれていること）

## エンジン名の誤り

`ocr_engine=vlmm`（誤字）: **422**（期待 422 — 黙って既定へ落とさない）
detail: `unknown ocr engine 'vlmm'. allowed: document_understanding, vlm`

判定: **PASS**
