# 2026-08-01 報告書の命名と置き場を目的別に分ける（loop-doctor R4 / R5 / R6）

- 対象 run: `_renders/` に溜まった 31 ファイル（RP-01.html / RP-01-explain.html / RP-01-stop.html /
  SYNC-01.html / SYNC-01-report.html / wave3-final.html / wave3-report.html …）
- 対象ファイル: `loop-config.yml` / `docs/guides/report-pipe.md` /
  `.claude/skills/loop-protocol/references/report-style.md` / ホーム側 `~/.claude/skills/preview/SKILL.md`
- 承認: 2026-08-01 ユーザー承認

## 症状

1. 報告書が「現在のフォーマット」で必ず作られるとは限らない（様式の選択がスキルの判断に委ねられていた）
2. ファイル名から中身が分からない
3. 目的の違う HTML が同じ場所に混ざっている

## 証跡

`_renders/` の 31 ファイル。日付が入っているのは 1 件だけで、しかも並びが逆（タイトルが先）。
同じタスクで 3 種類（`RP-01.html` / `-explain` / `-stop`）が目的の分からない名前で並んでいた。

設定側（`loop-config.yml`）は `topic.task: "<TASK>"` ＝ **タスク ID がそのままファイル名**で、
①日付が入らない ②目的が入らない ③オーケストレータが出す補助資料（説明・判断依頼）の規約が無い
（そのため `-explain` / `-stop` / `-decision` を場当たりで付けていた）。

## 根本原因

置き場と命名の規約が、**ループの完了報告しか想定していなかった**。実際には
「完了報告」「PR の承認依頼」「実装計画の承認依頼」「調査結果・説明」の 4 種類が流れている。

## 変更

- **R4 命名**: `<YYYY-MM-DD>_<内容がわかるタイトル>.html`。日付を先頭にして時系列に並べ、
  タイトルには内容を書く（タスク ID を名前にしない。ID は本文の脚注へ）
- **R5 置き場**: `_renders/reports/`（読み物）と `_renders/decisions/`（承認を問うもの）に分ける。
  **承認・可否・選択を 1 つでも問うているなら decisions**。迷ったら decisions へ倒す
- **R6 様式**: 長文構成（要点 → 目次 → 主張見出し → 根拠 → 次のアクション）を**既定**にした。
  短い承認依頼だけ簡易様式を許す

ADR-0018 の分担どおり、**様式と契約はリポジトリ側**（上記 3 ファイル）、
**置き場の解決はホーム側スキル**（`preview`）に書いた。

## 既存ファイルの扱い

**分類のみ実施し、改名はしていない。** Obsidian の埋め込み `![[name.html]]` はファイル名で
解決するため、ディレクトリ移動ではリンクが切れないが、**改名すると切れる**。
新しい命名は今後の分から適用する。

## 検証

次に報告書を出したときに `_renders/reports/` または `_renders/decisions/` へ
`YYYY-MM-DD_タイトル.html` で置かれることで判断する。
