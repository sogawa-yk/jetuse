# 2026-08-01 報告書はオーケストレータが書く（ループには書かせない）

- 対象ファイル: `loop-config.yml` / `.claude/skills/loop-protocol/SKILL.md` /
  `docs/guides/report-pipe.md`
- 承認: 2026-08-01 ユーザー指示（**永続設定**）

## 症状

**ループとオーケストレータの双方が報告書を作っていて二重になっていた。**
施主の評価は「**オーケストレータが書いたものの方が読みやすい**」。

## 原因

ループは実装の文脈に近すぎて、実装者視点（判定・差分・findings の羅列）になりやすい。
`report-style.md` で様式は決めていたが、**書き手の距離**までは制御できない。
オーケストレータは実装から一歩離れており、施主が知りたい粒度（何ができるようになったか /
何を判断すればよいか）で書ける。

## 変更

- `loop-protocol/SKILL.md`: 「人間ゲートに出すタスクパケット（HTML）」の節を
  「**完了ゲートで人間へ返すもの（HTML は作らない）**」へ置換。停止時は
  task / verdict / checks / e2e / residual / human_gates / decisions_needed / surprises を
  **構造化して最終メッセージに返す**だけにした。residual は要約させない。
  `surprises`（想定と違ったこと・自分の誤り）を明示的に返させる欄を追加した。
- `loop-config.yml`: `report.writer: orchestrator` を追加。`topic` は廃し、
  オーケストレータ側の規約（命名・目的別ディレクトリ・様式・レンダリング確認）だけ残した。
- `docs/guides/report-pipe.md`: 契約は「オーケストレータがホーム側スキルへ配置を頼むとき」に
  適用する、と冒頭に明記。

## 副次的な効果

ループ側の HTML 生成・レンダリング確認・配置がまるごと不要になる＝**そのぶんのトークンを使わない**。
1 タスクあたり毎回発生していたコスト。

## 検証

次のタスクで、ループが HTML を作らずに構造化事実を返し、オーケストレータがそれを材料に
`_renders/reports/` へ `YYYY-MM-DD_タイトル.html` を置くことで判断する。
