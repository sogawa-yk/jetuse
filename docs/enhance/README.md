# 改善要望（ER）

**目的**: 実装した方がよいと気づいたことを**その場で置いておき**、後から取りこぼさないための置き場。
いま進めている実装に集中できるように、**ここは急かさない**（既定の状態は「積んである」）。

- **1件1ファイル**（`ER-XXXX-<短い題>.md`）。詳細はリポジトリ側に置く（実装者が読む）
- **概要は Obsidian のレポート**で見る（判断する人が読む）。生成は `ops/er.py report`
- **この一覧は自動生成**（`ops/er.py index`）。手で編集しない

## 使い方

```bash
python3 ops/er.py list                 # 一覧を見る
python3 ops/er.py index                # この README の表を更新する
python3 ops/er.py report               # Obsidian へ概要レポートを出す
```

**思いついたら書く。** `_TEMPLATE.md` を写して番号を振り、`ops/er.py index` を実行する。
**その場で判断しない**——`status: parked` のまま積んでおき、
次に何をやるか決めるときに Obsidian のレポートから選ぶ。

## 着手するとき

1. ER を読み、`tasks/<ID>.md` に作業指示書を書く（完了条件・E2E・非ゴールまで）
2. ER の `status` を `doing` に、`ticket` に作業指示書のパスを書く
3. `[GOAL="..."] .claude/loop/start-loop.sh <ID>` でループを起こす
4. PR が出たら ER の `pr` を埋め、マージ後に `status: done`
5. `ops/er.py index && ops/er.py report` で両方を更新する

**`status` と `pr` を書き換えたら必ず両方を再生成する。** 手で表を直すとずれる。

## 書くときの約束

- **顧客名・顧客固有の固有名詞を書かない**（社名・社内システム名・顧客の文書名・社内コード体系）。
  一般語に伏せる。ER は git に載るため。
- **「実害」は実際に踏んだものだけ**。想像で書いたものは `気づき` か `構想` にする。
  この区別が、後から拾うときの優先順位になる。
- 根拠に**数字を書く**。推測なら「推測」と明記する。
