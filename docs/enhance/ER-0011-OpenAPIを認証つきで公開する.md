## ひとことで

コーディングエージェントが JetUse API を正しく呼べるようにする。**ただし認証とセットで出す。**

## 何ができないか

いま JetUse には**機械可読の仕様が無い**。`/openapi.json` は FastAPI が生成しているが、
API Gateway が `/api/*` しか通していないため**外部から取れない**（実測 404）。

エージェントは**仕様に無いことを推測（＝でっち上げ）する**ので、
仕様が無いと「正しく呼べるか」がそもそも決まらない。

## 根拠

本セッションで、起票者自身が JetUse API の利用者として詰まった実例:

- `agent` と `rag` が排他だと **400 を食らって初めて**知った
- エージェントで文書検索するには `enabled_tools` が要ることに**動かして**気づいた

いずれも**仕様があれば読んで避けられた**。

## 実装は完了している（未マージ）

ブランチ `feat/API-01`（`ec2c6cf`）に置いてある。review-10 まで回して**指摘ゼロ**、
実環境 E2E 5 シナリオ。内容:

- OpenAPI を `/api/` 配下から取得できるようにする
- **エラー応答（400 / 409 / 422）の意味と形**を仕様に載せる（自己修正に要る）
- 排他・依存・似た名前の使い分けを**説明文から読み取れる**ようにする
- 例を付ける
- 能力登録簿と OpenAPI の**ずれをテストで検出**する

## なぜ止めているか

**2026-08-04 の判断: 無認証で仕様を公開しない。**

いまの配備は `auth_required = false` / 許可 IP `0.0.0.0/0` で開いている。
この状態で仕様を出すと、**攻撃面の地図を無認証で配る**ことになる。

## 順序

**ER-0004（認証つきで呼べるようにする）が先。** 認証が入ってから、この実装をマージする。
当初は「仕様が先、認証が後」と考えていたが**逆**だった。

## やらない場合の代償

エージェントから使うたびに**推測で呼ばれる**。SDK も生成できない。
ただし**無認証で出すよりはまし**なので、認証を待つ。
