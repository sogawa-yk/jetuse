## ひとことで

初回だけブラウザで認証し、以後はエージェントが自動で呼べる状態にする。

## 何ができないか

いま JetUse を認証つきで使う口が無い。**受け取る側（token の検証）は実装済み**だが、
**取りに行く側**（ログインして token を保存する仕組み）が無い。

## 根拠

2026-08-04 に Identity Domain の対応状況を実測:

| 方式 | 対応 |
|---|---|
| PKCE 付き認可コード | **対応**（S256） |
| デバイスコード | **非対応** |
| 動的なクライアント登録 | **非対応** |

→ **「初回だけブラウザが開く」形は作れる**が、**アプリの事前登録が必ず要る**。
MCP にしても動的登録が使えないため、**この工程は消えない**。

## どう直すか

1. Identity Domain にアプリを1つ登録（**IAM 変更＝人が実施**）
2. ログイン用の小さな CLI（ブラウザを開き、手元で受け取り、token を保存）
3. 必要になれば MCP サーバー

## これを先にやる理由

**ER-0011（OpenAPI を公開する）が、これを待っている。**
認証が無い状態で仕様を出すと、無認証で攻撃面の地図を配ることになる。
ER-0011 の実装は**完了してブランチに置いてある**ので、**ここが済めば即マージできる**。

## やらない場合の代償

無認証で開けたままにするか、長期有効な鍵を配ることになる。
**誰が使ったか分からない**状態が残る。
