## ひとことで

一覧の2ページ目以降を取りに行くとき、特定の文字を含むトークンで失敗しうる。

## 何が起きるか

`infra/terraform/modules/hosted-agent/scripts/lib.sh` で、
`opc-next-page` のトークンを**URL エンコードせず**にクエリへ連結している。

実 API が `+` `&` `%` を含むトークンを返すと、**2 ページ目以降の取得に失敗**する。
失敗すると「もう無い」と解釈されうるので、**リソースの取りこぼし**につながる。

## 根拠

PR #128 のレビューで指摘（非 blocker として残した）。
**モックのトークンは `P2` のみ**なので、テストでは検出できない。

## どう直すか

トークンを URL エンコードしてから連結する。
あわせてモックのトークンに**記号を含むもの**を混ぜ、テストで検出できるようにする。

## やらない場合の代償

ページ送りが必要な規模（アプリが多数ある環境）で、**削除や所有権確認が取りこぼす**。
いまの規模では起きないが、**起きたときに気づきにくい**類の不具合。
