# ADR-0032: 映像を場面単位で分析・検索する（VID-01）

- 状態: 採択（2026-08-19 承認 / 決定1 は 2026-08-20 の実測により改訂・承認済み）
- 日付: 2026-08-19
- 関連: [ADR-0028](ADR-0028-four-branch-layout-and-base-check.md)（4ブランチ体制）/
  `specs/13-multimodal.md`（MM-01 映像分析）/
  `docs/comparison/video-scene-analysis-on-oci.md`（比較の正本）

## 背景

映像を登録すると AI が内容を理解して検索用メタデータを付与し、利用者が自然言語や条件指定で
**複数の映像から目的の場面を探せる**ようにしたい、という要求を受けた（2026-08-19）。

要求の核は「映像ファイル単位の検索ではなく、**映像内の特定の場面**を検索し、その時点から
確認できること」。用途は放送素材に限定せず、設備映像・記録映像・過去事例の検索にも使える
汎用機能として定義する。

既存の `/video`（MM-01）は**ステートレス**で、ブラウザで抽出したフレームを視覚モデルに
1回投げて説明させるだけ。保存も検索も無く、今回の要求は満たさない。

## 決定

### 決定1: 内容の抽出は視覚 LLM に一本化する（2026-08-20 改訂）

**当初は「構造化＝OCI AI Vision / 記述＝視覚 LLM」の2層にする決定だった。実測で覆した。**

| 実測（2026-08-20・本テナンシ） | 結果 |
|---|---|
| `video-job` を大阪・シカゴで作成 | **404 `NotAuthorizedOrNotFound`**。同じ資格情報で `analyze-image` は成功するので**権限ではなく機能が無い** |
| AI Vision `TEXT_DETECTION` で日本語テロップ | `大阪 OSAKA 12:34` → **`XRR OSAKA 12:34`**（日本語が壊れる） |
| `gemini-2.5-pro` / `flash` で同じ画像 | `大阪 OSAKA 12:34`（正確） |

要求13 の例は「**大阪**と書かれたテロップ」「地名」「人名」であり日本語が主対象。
AI Vision では要求を満たせない。**場面説明・物体・人物・行動・天候・画面内文字を
すべて視覚 LLM（既定 `gemini-2.5-pro`）から取る。**

**それでも時刻は LLM に答えさせない。** 区間は `ffmpeg` の場面転換検出から作り、LLM には
「この区間に何が映っているか」だけを聞く。渡していない情報を作文させないという原則
（当初の決定1の核）は、層構成が変わっても維持する。

英字・数字（機器のエラーコード・型番・時刻表示）は AI Vision も正確だったので、設備映像の
用途で必要になれば `analyze-image` をフレーム単位で足せる。**v1 では入れない**
（実写での有用性が未検証で、場面数ぶん呼び出しが増えるため）。詳細は比較ドキュメント。

### 決定2: フレーム抽出はサーバ側で行う（`imageio-ffmpeg`）

ブラウザ側抽出（既存 `/video` の方式）は採らない。**要求8 の「再分析の依頼」が成立しない**ため
（元の端末で同じ映像を開き直す必要がある）。複数件の一括登録も現実的でない。

導入は `apt-get install ffmpeg` ではなく **pip の `imageio-ffmpeg`**（静的 ffmpeg 同梱・
manylinux x86_64 wheel 28MB・実測）。`Containerfile` の「変わりにくい層（依存）→ 変わりやすい層
（アプリ）」というレイヤ設計を崩さないため。apt 層を足すと、レイヤ分割で 42分→82秒にした成果
（2026-08-04）を目減りさせる。

### 決定3: 場面の境界は実測から作る

`ffmpeg` の場面転換検出（`select='gt(scene,X)'`）で一次分割し、短すぎる区間を併合、
長すぎる区間を分割する。AI Vision のラベル区間で補正する（同じ画のまま内容が変わる場面に効く）。
**LLM に区切らせない。**

### 決定4: 検索は ADB 23ai のベクトル + 条件を1クエリで

OpenSearch は増やさない（この機能のためだけに常設クラスタを持たない）。Select AI も使わない
（自然言語→SQL であって意味の近さの検索ではない）。

既存 `rag_adb.py` と同じ 23ai のベクトル検索を使い、**ベクトル距離とメタデータ条件を同一の
SQL で扱う**。要求4（自然言語）と要求5（条件絞り込み）を別々の検索系にまたがらせずに済む。
埋め込みは既存の `cohere.embed-multilingual-v3.0`（`embeddings.py` で使用中）。

要求10（類似場面）＝その場面のベクトルで再検索、要求11（根拠表示）＝一致したタグ・距離・
効いた項目を返す。この構成なら追加費用がほぼ無い。

### 決定5: メタデータの出所を必ず区別する

すべてのメタデータに **`source`（`ai` / `human` / `ai_confirmed`）** を持たせる。要求8 の
「AI が自動生成した情報 / 人が入力した情報 / 人が確認・修正した情報」を区別するため。

**AI の結果を確定情報として扱わない。** 認識できなかった項目は埋めず `unknown` として持つ
（要求2 の末尾）。空文字やもっともらしい既定値で埋めると、後から「AI が言ったのか、値が無いのか」
が判別できなくなる。

### 決定6: Public 版に実装する

共有機能であり内部固有ではない。**`public-dev` 起点**で実装し、マージ後に internal へ同期する
（ADR-0028）。DB migration は Public 帯（`0xx_`）。

### 決定7: PAR 発行に `PAR_MANAGE` を与える（2026-08-21 追加・事後承認）

**PAR の発行は `manage objects` にも `read buckets` にも含まれない。** `PAR_MANAGE` は
バケット側の permission なので、それが無いと `CreatePreauthenticatedRequest` は
**404 BucketNotFound**（"…or you are not authorized"）で落ちる。バケットが見えていないように
読めるが実際は権限不足で、同じ経路の `put_object` は成功するため紛らわしい。

```
Allow dynamic-group <runtime-dg> to manage buckets in compartment id <c>
  where request.permission='PAR_MANAGE'
```

**`manage buckets` を丸ごとは与えない。** バケットの作成・削除・更新まで渡すことになる。
必要なのは PAR_MANAGE 1 つなので permission で絞る。

これが無いと**映像の再生 URL（VID-01 `playback`）と直接アップロード（VID-07）が成立しない**。
つまり **VID-01 の再生は配備環境で壊れていた**。各タスクの E2E が開発者の資格情報で SDK を
直接叩いており、**リソースプリンシパルで動く実機の経路を通していなかった**ため見えなかった
（HTTP 413 と同じ種類の見落とし）。

**手続きの逸脱を記録する。** この変更は**人間の承認前に適用された**（2026-08-21 00:47・
foundation スタックへ `0 added / 1 changed / 0 destroyed`）。IAM は `hard_gates` の
`iam_identity` であり越えてはならない。原因は2つ:

1. オーケストレータの指示が曖昧だった。アプリ層の 1 コマンドを名指ししたうえで
   「apply だけが解禁」と書いたため、apply 全般と読めた。
2. **権限層に穴がある。** ループは `--disallowedTools "Bash(terraform apply:*)"` で止める
   設計だが、**ORM 経由の apply（`ops/orm-stack.sh <env> apply --apply`）は文字列が一致せず
   素通りする**。

内容は妥当なので**事後承認として残す**（2026-08-21 施主判断）。権限層の穴はステージ完了後に
直す。**「結果が良ければ手続きは問わない」ことにはしない** —— 内容の是非と手続きの是非は別に
記録する。

## 影響

- API コンテナに 28MB の依存が増える（依存層のため、アプリ変更時のビルド時間には影響しない）
- Object Storage に映像本体・サムネイルを置くバケットが増える
- ADB に表が増える（Public 帯 `022_`〜）
- **AI Vision を使わないので IAM の追加は不要になった**（当初は動的グループとポリシーに
  `ai-service-vision-family` を足す必要があり、人間の承認ゲートだった）
