# タスク: VID-06 UI（一覧・検索・プレーヤ＋タイムライン）

## 目的
利用者が映像全体を最初から確認しなくても、**目的の場面へ直接移動できる**こと。この機能の主要な価値。

## 仕様参照: specs/20-video-search.md §6

## 前提
- VID-04（検索）/ VID-05（編集）

## 作業内容
- `/videos` — 一覧・登録（**複数選択可**）・分析状態・条件絞り込み
- `/videos/search` — 自然言語入力＋条件パネル。結果は**場面カード**
  （サムネイル・開始/終了時刻・説明・**一致理由**・映像の基本情報）
- `/videos/{id}` — プレーヤ＋**タイムライン**（場面帯を種別で色分け・選ぶとその時刻へ移動）。
  場面ごとの編集・確認・再分析
- 検索結果を選ぶと `/videos/{id}?t=<秒>` で開き、**その時刻から再生**する
- 既存 `/video`（MM-01 のステートレス分析）は残す。ナビの導線を整理する

## 完了条件
- 実 OCI で: 複数登録 → 分析 → 自然言語検索 → 結果を選ぶ → **該当時刻から再生** → 修正 → 再検索
- タイムラインの帯を選ぶとその場面へ移動すること
- 一致理由が画面に出ること
- 既存の UI 規約（`specs/01-design-system.md`）に合わせる

## 前タスクの残（VID-04 / VID-05 の Codex 指摘。UI から見える形なので取り込む）
- `video_search.py`: 根拠文の「N件中」が**全一致件数ではなく返した行数**を使っている。
  1000 件一致していて limit=20 でも「20件中」と出る。**UI の件数表示が嘘になる**ので直すこと。
- `video_search.py`: 同一サムネイルを含む検索が並行すると同じ object の PAR を重複発行する。
  UI は一覧で多数のサムネイルを引くので**ここが一番踏みやすい**。
- `video_search.py`: `limit` を `int(limit)` で変換しており、`True` が 1 件として通る等
  API スキーマと違う規則になっている。スキーマ側で弾くこと。
- `video_edit.py`: 埋め込み生成後の競合検査が、上書き後の値から文字列を再生成して比較しており、
  **別リクエストが同じ項目を先に更新していても検知できない**。UI は編集画面から連続で
  保存できるので、ここも踏みやすい。

## 禁止事項
- 検索結果に理由を出さないこと（要求11）
- 場面へ移動できない検索結果を出すこと
