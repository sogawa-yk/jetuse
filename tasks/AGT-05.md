# タスク: AGT-05 文書検索をツール往復の予算から外す

## 目的
**チャンク単位の出典（`agent_rag_backend=adb`）を選ぶと、業務 API に使える往復が 2 割しか残らない。**

AGT-04 で `adb` を選べるようにしたが、この経路の `rag_search` は **function tool** なので
**1 回の検索が 1 ホップを消費**する。従来の `vector_store` 経路は `file_search` **built-in** で
**ホップを消費しない**。つまり **出典を細かくするほど業務 API の予算が減る**という不整合がある。

AGT-04 の ADR-0025 §1 はこれを「副作用」として認識していたが、**影響の大きさを見誤った**。
既定値 24 は「1 ステップ = 検索 1 + API 1」を前提に置いたが、**実測は 1 API あたり 3〜5 回**検索する。

## 実環境で確認した事実（推測ではない）

実案件のデモ（API 8 本の受付フロー・仕様書 8 冊・`agent_rag_backend=adb`）を 3 回実行:

| 実行 | 文書検索 / 全ツール呼び出し | 業務 API 成功 | 自己修正 | 打ち切り |
|---|---|---|---|---|
| 1 | **20 / 24** | 0 | 0 | `max_tool_hops` |
| 2 | **22 / 24** | 1 | 0 | `max_tool_hops` |
| 3 | **19 / 24** | 2 | 1 | `max_tool_hops` |

**3 回とも上限で打ち切り。業務 API に回せたのは 4〜5 回分だけ。**
エージェント自体は正しく振る舞っている（先頭 2 本を正しい順序で呼び、422 から自己修正し、
409 の順序違反から前段へ戻っている）。**足りないのは予算の配分**である。

## 決まっていること（2026-08-02 人間ゲートで承認済み。作り直さない）

**文書検索をツール往復の予算から外す。** 業務の操作とは別に数える。

- 従来の `vector_store` 経路（built-in）は**元々ホップを消費していない**。
  `adb` を選ぶと消費するのは**不整合**であり、揃えるのが本来の姿。
- **上限を上げる案は採らない。** 対症療法であり、検索が増えればまた足りなくなる。
  コストは往復数に対して概ね二次で効くので、上げ幅がそのまま効く（ADR-0025 のコスト表）。

**無制限にはしない。** 検索には**別の上限**を設ける（同じ検索を繰り返して止まらなくなるのを防ぐ）。

## 作業内容
- ホップの計上を「**業務の操作（外部 HTTP ツール・MCP・組込ツール）**」に限る。
  `rag_search`（`adb` 経路の function tool）は**別枠**で数える。
- 文書検索の回数に上限を設ける（例 `AGENT_MAX_DOC_SEARCHES`）。**根拠を添えて既定値を提案し、
  判断を上げること**（実測: 1 API あたり 3〜5 回 × API 8 本）。
- 検索の上限に達したことも `limit_reached` で通知する（`reason` で区別できるようにする）。
  **黙って打ち切らない**——どちらの予算で止まったかが分からないと、設定のどちらを直せばよいか追えない。
- **同じ検索の繰り返しを検知して知らせるか**は判断を上げること（実測で同一クエリの反復がある）。
  勝手に握り潰すと、エージェントが「調べた」と思ったまま結果を得られない状態になりうる。
- `vector_store` 経路の挙動は**変えない**（元々消費していない）。
