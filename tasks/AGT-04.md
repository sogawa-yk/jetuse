# タスク: AGT-04 エージェントモードを多段の業務フローに耐えるようにする

## 目的
**エージェントモードが、複数の業務 API を順に呼ぶ手続きを最後まで実行できない。**

実案件のデモ（API 8 本を順に呼ぶ受付フロー）を実行して、2 つの原因を実測した。
どちらも「エージェントに業務 API を渡す」という JetUse の看板機能に直結する。

## 実環境で確認した事実（推測ではない）

エージェントに 8 本の HTTP ツールと文書検索を渡し、手順を書かずに手続きを依頼した実行結果:

| 事実 | 値 |
|---|---|
| 業務 API の呼び出し | **6 回**（うち成功 4・自己修正 1） |
| 文書検索（`rag_search`）の呼び出し | **約 40 回** |
| 到達点 | 8 本中 4 本。**途中でホップ上限に当たって停止** |

### 原因 1: `MAX_TOOL_HOPS = 5` が固定で低すぎる
`packages/api/jetuse_core/chat.py:291`。**API 8 本の手続きに、間の文書検索が挟まる**ので
5 往復では入口にも届かない。診断のため一時的に 30 へ上げたところ 4 本まで進んだ
（**この変更はコミットしていない**）。それでも完走しなかった。

### 原因 2: エージェントモードで**チャンク単位の出典**を使えない
- `agent` と `rag` は併用できない（`service/routes/chat.py:222` で 400）。
- エージェントモードの文書検索は `rag_search` のみで、実体は **Vector Store の
  `file_search` built-in**（`jetuse_core/chat.py:364`）。**`adb` バックエンドは未接続**。
- そのため出典は**ファイル単位**（「どの仕様書か」）にとどまり、
  「どのシートのどのセルか」が返らない。**エージェントが同じ文書を何度も引き直す**
  （上の約 40 回）。ADR-0020 が「Oracle AI Database ならチャンク単位で出せる」と決めた
  能力が、**エージェント経路では活きていない**。

**2 つを同じタスクで直す。** 別々に直すと、どちらか一方では
「業務フローが最後まで通る」という完了条件を確かめられない（E2E が共通のため）。

1. **ホップ上限を設定可能にし、既定を業務フローに耐える値へ上げる。**
2. **エージェントモードの文書検索で `adb` バックエンド（チャンク単位の出典）を使えるようにする。**

## 作業内容

### 1. ホップ上限
- `MAX_TOOL_HOPS` を設定（env / settings）で変えられるようにする。**上限（天井）も設ける**
  ——無制限にすると、モデルが同じツールを呼び続けたときに止まらない。
- 既定値は**根拠を添えて**決める（実測: API 8 本 + 文書検索。1 ホップに複数呼び出しが載る
  ことも含めて見積もる）。**判断を上げること**（下記）。
- **上限に当たったことを利用者が分かる形にする。** 現状は「ツールなしで最終回答を強制」
  するだけで、途中で力尽きたのか答え切ったのかが**外から区別できない**。
  デモの画面で「なぜ途中で止まったか」を出せないと、失敗の説明ができない。

### 2. エージェントモードでのチャンク単位の出典
- エージェントの文書検索を `adb` バックエンドでも実行できるようにする
  （`rag_search` を function tool として実装し、`rag_adb` の検索を呼ぶ形が素直）。
- **出典（シート名・セル範囲）を結果に載せる。** 載らないなら、この作業の意味が無い。
- どのバックエンドを使うかは**要求で選べる**ようにする（既定は現行維持＝挙動不変）。
- `agent` と `rag` の併用禁止は**維持する**（併用したときに何が起きるかが不明瞭なままなので、
  今回はエージェント側の口を増やすだけにする。禁止を外すなら別タスク）。

## 判断を上げること（実装せず ADR に書いて止める）
- **ホップ上限の既定値と天井**。「足りないから上げる」を繰り返さないよう、
  実測（API 8 本 + 文書検索）を根拠にした値を提案し、判断を上げること。
  コスト（1 ホップ = モデル 1 往復）にも触れること。

## 非ゴール / 禁止事項
- `agent` と `rag` の併用禁止を**外さない**（別タスク）。
- Vector Store 経路の `file_search` built-in を**置き換えない**（増やすだけ）。
- 検索回数を減らすために**検索結果を勝手に切り詰めない**（根拠が欠ける）。
- **顧客名・案件名を書かない**（公開リポジトリ）。認証情報・OCID をコミットしない。
- IAM を変更しない。未承認のコミット / PR / push を行わない（人間ゲート）。
