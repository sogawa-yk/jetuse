# タスク: TOOL-01 デモ固有の HTTP ツールをエージェントに渡せるようにする

## 目的
**案件デモが持つ業務ロジック（HTTP エンドポイント）を、JetUse のエージェントにツールとして
渡せるようにする。** これが無いと、デモ側は「AI 部分は JetUse に任せる」が成立せず、
エージェントの実行ループを自前で持つことになる。

2026-07-28 に合意した論点 B（合意時の報告書は各自の閲覧環境。ここでは要旨のみ引く）:

> デモ固有ツールをエージェントへ渡す口を **JetUse の一級機能**にする

RAG 側（論点 C・F）は SPIKE-M1 → RAGM-01/02/03/04 → PREP-01/02/03 で実装済み。
**論点 B だけが手つかず**で残っている。

## 現状（調査済み・作り直さない）
| 既にあるもの | 何ができるか | 何が足りないか |
|---|---|---|
| `TOOLS`（組込） | web検索・Web取得・RAG検索・DB照会など | **コードに書いた分だけ**。利用者が足せない |
| MCP サーバ登録（`/api/agent/mcp-servers`） | 外部の MCP サーバを繋ぐ | **デモ側が MCP サーバを立てる必要がある**。単なる HTTP API を繋ぐには重い |
| `/api/agent/execute-tool` | ツールを単発で実行 | エージェントの実行ループに**配線されない** |

**足りないのは「素の HTTP エンドポイントを、スキーマ付きでツールとして登録し、
エージェント実行時に自動で配線する」口。**

## 作業内容
### 1. ツール登録（永続・所有者ごと）
- 登録するもの: `name` / `description`（**LLM がいつ使うかを判断する材料**）/
  `parameters`（JSON Schema）/ 呼び出し先 URL / HTTP メソッド / 認証（下記）。
- 既存の `usecases` / `mcp_servers` と同じ所有者強制の流儀に載せる（SQL の WHERE 句・0 行 = 404）。
- **`ToolDef` の形に寄せる**。組込ツールと外部ツールが同じ枠で扱えること
  （`chat.py` の `_build_tools` が両方を同列に組み立てられる形）。

### 2. 実行
- エージェント実行中にモデルがそのツールを呼んだら、**JetUse がサーバ側で HTTP を代理実行**して
  結果をモデルへ返す。ブラウザから直接叩かせない（秘密が漏れる）。
- **タイムアウト・レスポンスサイズ上限・リトライしない**を既定にする。
  上限超過は「ツール実行が失敗した」ことをモデルに伝える（黙って切り詰めない）。

### 3. 認証（秘密の扱い）
- デモ側 API が秘密ヘッダを要求する場合に備え、**秘密は Vault に置き、OCID で参照する**。
  既存の `mcp_servers` が `auth_secret_ocid` を持っているので**同じ流儀に揃える**（新方式を作らない）。
- **秘密を DB の平文列やリクエストボディに置かない。**

### 4. 安全側の作り
- **登録できる URL を制限する**（`mcp_servers.validate_url` の流儀を確認して揃える）。
  内部メタデータエンドポイント（169.254.169.254 等）やループバックへの到達を防ぐ。
  **SSRF の入口になりうる機能**なので、ここは fail-closed に。
- 1 エージェントに渡せるツール数の上限を決める（LLM の選択精度が落ちるため）。

### 5. 能力カタログ
- `capabilities.py` の `agents` ディスクリプタに、外部ツールを渡せることを記載する
  （RAGM-03 と同じ枠組み。**未実証の項目を「できる」と書かない**）。

## 非ゴール / 禁止事項
- **MCP サーバ登録の作り替えをしない**（別経路として共存させる）。
- デモ専用のサーバコードを JetUse 側に持たない（specs/17 §1）。**渡す口を作るだけ**。
- ツールの中身（業務ロジック）は作らない。検証用の架空 API は使い捨てでよい。
- **秘密を平文で扱わない。** 新しい秘密管理方式を発明せず、既存の Vault 参照に揃える。
- 顧客データ・顧客名を持ち込まない（公開リポジトリ）。認証情報・OCID をコミットしない。
- IAM を変更しない。権限不足が出たら blocked にして報告する。
- 未承認のコミット / PR / push を行わない（人間ゲート）。
