# タスク: TOOL-02 外部HTTPツールに追加ヘッダと冪等キー発行を持たせる

## 目的
**外部HTTPツールに認証ヘッダを1つしか添えられず、必須ヘッダが複数ある API を呼べない。**

TOOL-01 は `auth_header` + `auth_secret_ocid` の**1組だけ**を送る設計になっている。
実案件のデモで、**認証以外に2つのヘッダを必須とする API** に当たり、
**エージェントから一切呼べない**ことが判明した（顧客案件の検証。実装は公開可能な一般機能として行う）。

## 実環境で確認した事実（推測ではない）
| 事実 | 内容 |
|---|---|
| 対象 API が必須とするヘッダ | 認証キー / 追跡 ID / **冪等キー** の 3 つ |
| 手動での疎通 | **3 つ揃えれば 200 で成功**（API 側は正しく動作している） |
| 不足時の応答 | `400 MISSING_CORRELATION_ID` / `400 MISSING_IDEMPOTENCY_KEY` |
| JetUse 経由 | **登録すら意味を成さない**（必ず 400 になる） |

## この件で「ゲートウェイ側で固定値を注入する」回避策を採らない理由
**冪等キーは呼び出しごとに変わる前提の仕組み**である。固定すると
**同一パスへ異なるボディで 2 回目を呼んだ時点で `409 IDEMPOTENCY_KEY_REUSED_WITH_DIFFERENT_INPUT`** になる。

このデモの測定対象はまさに「**エージェントがエラーから自己修正して呼び直せるか**」であり、
そこが機構の都合で機械的に拒否されると、**エージェントの能力ではなく仕掛けの制約で失敗する**。
**測定値が意味を失う**ため、回避策ではなく本体側で解決する（2026-08-02 人間ゲートで承認済み）。

## 決まっていること（2026-08-02 人間ゲートで承認済み。作り直さない）

### 1. 固定ヘッダを数個添えられるようにする
登録時に「毎回この値を付ける」ヘッダを指定できる（`headers`）。
**認証以外の必須ヘッダを持つ API は一般的にあるため、案件専用機能にしない。**

### 2. 冪等キーは **JetUse が呼び出しごとに発行する**
ヘッダ名だけ登録すれば（`idempotency_header`）、**呼び出しのたびに新しい値**を JetUse が生成して送る。

**モデルに作らせない。** 番号を作るのは「呼ぶ側」の責任であり、呼んでいるのは JetUse である。
モデルに任せると**使い回す**（＝二重実行防止が効かなくなる）。**ここは設計判断なので ADR に残す。**

## 作業内容
- `HttpToolCreate` に `headers: dict[str,str] | None` と `idempotency_header: str | None` を追加。
- 保存先のマイグレーション（`021_*.sql`）。既存ツールは両方 NULL で動作が変わらないこと。
- `call_tool` でのヘッダ組み立て順を **固定ヘッダ → 冪等キー → 認証 → Host** にする。
  **後から入るものが必ず勝つ**ので、固定ヘッダで認証・宛先を上書きできない。
- 検証（登録時・実行時の両方で。登録時だけだと後から DB を触られた場合に素通りする）:
  - ヘッダ名は HTTP トークン文字のみ。値は**印字可能 ASCII のみで CR/LF を含まない**（ヘッダインジェクション対策）。
  - **禁止ヘッダ**（大小無視）: `host` / `authorization` / `proxy-*` / `cookie` / `set-cookie` /
    `content-length` / `content-type` / `transfer-encoding` / `accept-encoding` / `connection` /
    `upgrade` / `expect` / `te`、および**そのツール自身の `auth_header`**。
  - 個数・長さの上限を設ける（`MAX_TOOLS_PER_AGENT` と同じ流儀で定数化）。

## 非ゴール / 禁止事項
- 動的な値の一般的なテンプレート機構（`{{...}}` 置換など）は作らない。**冪等キーだけを特別扱いする。**
- 既存の SSRF 防御（https 限定・私設アドレス禁止・IP ピン留め・リダイレクト拒否）を**緩めない**。
- 秘密を平文で受け取る口を作らない。
- **顧客名・案件名を書かない**（公開リポジトリ）。認証情報・OCID をコミットしない。
- IAM を変更しない。未承認のコミット / PR / push を行わない（人間ゲート）。
