# タスク: API-01 OpenAPI 仕様を外部へ公開する

## 目的
**JetUse API に「何ができるか」の機械可読な仕様が外から取れない。**

FastAPI なので `/openapi.json` は**既に生成されている**が、API Gateway が `/api/*` しか
通していないため**外部から到達できない**（実測: `/openapi.json` `/docs` とも 404）。

デモ作成者が JetUse を使うとき、いま頼れるのは `docs/` と実装を読むことだけ。
**SDK を作る前に、まず機械可読の仕様を配れる状態にする**（SDK は仕様から生成できる）。

## 実環境で確認した事実（推測ではない）

| 確認 | 結果 |
|---|---|
| `GET /openapi.json`（配備済み・シカゴ） | **404** |
| `GET /api/openapi.json` | **404** |
| `GET /docs` / `/api/docs` | **404** |
| `service/main.py` の `FastAPI(...)` | `openapi_url` を**明示していない**＝既定 `/openapi.json` で生成されている |
| API Gateway のルート | `/api/chat/{p*}` / `/api/ocr` / `/api/rag/files` / `/api/rag/{p*}` / `/api/demos/{p*}` / `/api/{p*}` |

**＝ 生成はされているが、経路が無いだけ。**

## 併せて直す「分かりにくさ」（実際に詰まった点）

デモ作成者（本タスクの起票者が最初の利用者）が実際に時間を溶かした箇所。
**仕様を出すだけでは解決しない**ので、同時に手当てする。

| # | 症状 | 期待 |
|---|---|---|
| A | `agent` と `rag` を同時指定すると 400。**呼ぶまで分からない** | 仕様と説明文から**事前に分かる**こと |
| B | エージェントで文書検索するには `enabled_tools` に `rag_search` が要る（無いと検索されない） | 同上 |
| C | 取り込みは `rag_backend`、エージェントは `agent_rag_backend` と**名前が違う** | 少なくとも**仕様上で関係が読める**こと |

## 仕様参照
- `packages/api/service/main.py`（`create_app` / `FastAPI(...)`）
- `infra/terraform/modules/api-gateway/main.tf`（ルート定義）
- `packages/api/service/routes/capabilities.py`（能力登録簿。**仕様と二重管理にしない**）
- `packages/api/service/schemas.py`（リクエスト/レスポンスのモデル）

api（＋ infra）

- **`terraform apply` は人間ゲート。** ゲートウェイのルート追加は plan までで止める。

## 決まっていること（2026-08-04 人間ゲートで承認済み。作り直さない）

1. **OpenAPI 仕様を外部から取得できるようにする。**
2. **SDK は作らない。** 契約がまだ動いている（3 日で 6 回変わった）ため、
   いま SDK を作ると二重保守になり、**古い SDK が動いてしまう**という悪い状態を生む。
   仕様さえ出れば**生成できる**。

## 作業内容
- OpenAPI の公開経路を用意する。**`/api/` 配下に置く**のが素直
  （Gateway の既存ルート `/api/{p*}` にそのまま乗る＝ Terraform 変更が要らない可能性がある。
  **まず確かめること**。要るなら plan まで）。
- **説明文（description）を実用に足る水準にする。** 型だけの仕様は配れない。
  少なくとも上記 A / B / C が**仕様を読めば分かる**ようにする:
  - 排他の関係（`agent` と `rag`）
  - 依存の関係（エージェントの文書検索には `enabled_tools` が要る）
  - 似た名前の使い分け（`rag_backend` / `agent_rag_backend`）
- **能力登録簿（`/api/capabilities`）と二重管理にしない。** どちらが正かを決め、
  もう一方は導出するか、相互参照にとどめる。**ずれたら意味が無い**。
- 仕様が**実装とずれていないこと**をテストで固定する
  （例: 登録簿の各能力の route が OpenAPI に存在する）。
- 認証が要る配備（`auth_required=true`）で**仕様だけ無認証で晒さない**こと。
  晒す/晒さないの既定は**判断を上げる**（下記）。

## 判断を上げること（実装せず ADR に書いて止める）
- **仕様を無認証で公開してよいか。** 内部向け配備では便利だが、
  公開配備では**攻撃面の地図を配る**ことにもなる。既定をどちらにするか。

## 非ゴール / 禁止事項
- **SDK を作らない**（承認済みの判断）。
- 能力登録簿と OpenAPI の**二重管理を作らない**。
- 既存の API の**契約を変えない**（説明文の追加は可。パラメータ名の変更は別タスク）。
- `terraform apply` を実行しない（plan まで）。
- **顧客名・案件名を書かない**。認証情報・OCID をコミットしない。
- IAM を変更しない。未承認のコミット / PR / push を行わない（人間ゲート）。
